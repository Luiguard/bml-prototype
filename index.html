Das Problem

Jedes Mal wenn jemand eine Website öffnet, verbrennt dein Server CO₂.

Nicht wegen der Inhalte — sondern wegen des Formats. HTML ist ein Text-Format aus den 1990ern, das nie für Milliarden Seitenaufrufe täglich gedacht war.

Wie BWEB intern aufgebaut ist

Ein .bweb-File ist ein Binär-Container mit mehreren Sektionen — eine pro Aufgabe. Klicke auf eine Sektion für Details.

BML

Binary Markup Language

Ersetzt HTML-Tags durch 1-Byte-Codes. <div> → 0x01. Text bleibt als UTF-8.
Sektion ID: 0x00 · Struktur: [tagId u8][attrCount u8][6 Bytes Padding][Attribute...] · Text-Nodes: tagId=0xFD + [padding 3B][len u16][UTF-8]
BDT

Binary DOM Tree

Flacher Pointer-Baum. Jeder Node: 10 Bytes mit Parent, Child und Sibling-ID als uint16.
Sektion ID: 0x01 · Node: [id u16][parentId u16][firstChild u16][nextSibling u16][nodeType u8][flags u8] · 0xFFFF = kein Verweis
BLB

Binary Layout Blocks

Vorberechnetes CSS. 50 Bytes pro Node: x, y, Breite, Höhe, Farben, Abstände — kein Reflow nötig.
Sektion ID: 0x02/0x03/0x0A (Desktop/Tablet/Mobile) · Float32: x, y, w, h, pTop, pRight, pBottom, pLeft · RGBA: bg + fg je 4 Bytes · radius u16, zIndex i16, flags u8
BIB

Binary Image Blocks

Rohe Bilddaten (PNG/JPEG/WebP) inline — kein Base64-Overhead. Direkt an GPU via createImageBitmap.
Sektion ID: 0x04 · Index: [count u16][id u16][offset u32][len u32] per image · Data: rohe JPEG/PNG/WebP Bytes
BVS / BAS

Binary Video & Audio Streams

Video-Frames (VP8/VP9/H.264) und Audio-Samples, bereit für VideoDecoder / AudioDecoder.
BVS ID: 0x05 · BAS ID: 0x06 · Chunks: [isKey u8][pts u64][duration u32][dataLen u32][data] · Synchronisiert über PTS-Timestamps
TOC

Table of Contents (Multi-Page)

VFS-Index für mehrseitige Pakete. Navigation ohne Netzwerk-Request — alle Seiten im selben File.
Sektion ID: 0x09 · Format: "VFS" + 0x01 + JSON: {"index.html": {"index": 0}, ...} · Seitennavigation via VFS lookup intern
